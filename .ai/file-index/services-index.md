# Services Index

| File Path | Purpose | Relationships | Usage Patterns |
|---|---|---|---|
| `apps/api/src/auth/auth.service.ts` | First-party auth service (public sign-up OTP + password login/reset + sessions) | Used by `auth.controller` and `ClerkAuthGuard` compatibility guard | Issues/verifies sign-up and password-reset OTP challenges, stores/replaces password hashes, validates password credentials, revokes old sessions after reset, creates sessions, resolves signed-in user context, and computes post-login onboarding/dashboard redirect metadata |
| `apps/api/src/auth/auth.bootstrap.service.ts` | Startup default-account bootstrap service | Invoked from API startup path | Ensures env-configured test owner account exists without overwriting existing identity |
| `apps/api/src/customers/customers.service.ts` | Customer domain logic | Called by customers controller | Customer CRUD and visit logic; persists optional mobile as blank/null or normalized Philippine E.164 `+639...` values |
| `apps/api/src/billing/billing.service.ts` | Billing application logic | Calls Lemon Squeezy, billing catalog helpers, database ledger tables, AI/email usage sources, and webhook event storage | Billing catalog/status responses, hosted checkout creation, portal redirects, webhook-authority-only plan/cancel/resume lifecycle requests with pending-sync UX metadata, feature-flagged Lemon no-op fallback when self-serve billing is disabled, direct current-month UTC ledger lookup by `(organizationId, month)`, subscription/order webhook reconciliation with processed/ignored/failed event storage, verified-booking/SMS add-on balance and refund-unit updates, email and AI usage status assembly, unresolved-only refund-review warnings, delayed-sync warning surfacing, refund handling, and ignored-event recording |
| `apps/api/src/billing/lemonsqueezy.service.ts` | Lemon Squeezy provider client and webhook validator | Used by billing controller/service and billing webhook controller | Creates hosted checkout URLs, fetches fresh subscription portal URLs, updates/cancels subscriptions, and validates raw-body `X-Signature` HMACs with timing-safe comparison |
| `apps/api/src/billing/plan-catalog.ts` | Canonical plan and add-on catalog | Shared by billing, capacity, and web pricing surfaces | Free/starter/growth/pro definitions, growth booking override, and allowlisted variant env-key resolution |
| `apps/api/src/billing/credit-reconciliation.ts` | Credit ledger helper logic | Used by billing tests and future webhook/usage reconciliation flows | Deterministic included-plus-addon-minus-used remaining calculations and upgrade allowance math |
| `apps/api/src/billing/billing-env.ts` | Billing/runtime configuration validation | Called during API bootstrap | Fails fast on required Lemon Squeezy or Twilio Verify env gaps only when self-serve billing is enabled; stays permissive in free-cap mode |
| `apps/api/src/messaging/messaging.service.ts` | Message generation and dispatch logic | Uses AI execution, providers, metering | Message creation/send orchestration |
| `apps/api/src/messaging/message-dispatch.service.ts` | Automated message dispatch orchestration | Uses plan capacity, automation policy, SMS/email providers, and metering services | Finalizes message content, estimates SMS segments, enforces segment-aware credits, persists provider metadata, and retries only provider-marked safe SMS failures |
| `apps/api/src/messaging/messaging-webhook.service.ts` | Trusted provider delivery event processing | Called by messaging webhook controllers after signature validation | Maps Twilio/Resend delivery states, preserves terminal statuses, and stores raw provider metadata/failure reasons |
| `apps/api/src/messaging/twilio-webhook-validation.service.ts` | Shared Twilio webhook signature validator | Used by inbound SMS and status webhook controllers | Validates complete form params using Twilio's helper library and explicit public callback URL env vars with local-only fallback |
| `apps/api/src/messaging/sms-metering.service.ts` | SMS monthly/add-on segment metering | Used by SMS dispatch and billing status flows | Resolves current UTC month rows directly by `(organizationId, month)`, consumes included before add-on segment credits, and preserves add-on balances across month rollover |
| `apps/api/src/messaging/email-metering.service.ts` | Email monthly cap metering and usage tracking | Used by `MessageDispatchService`, `MessagingController`, and `PlanCapacityService` | Enforces plan-catalog-driven monthly email caps, resolves current UTC month rows directly by `(organizationId, month)`, and records per-send usage |
| `apps/api/src/ai/ai-execution.service.ts` | Guardrailed AI execution wrapper | Used by messaging and AI module | AI policy-bound text generation with structured request/success/error logging for OpenAI actions/responses, plus optional OpenAI `response_format` JSON-schema enforcement for deterministic assistant outputs |
| `apps/api/src/ai/ai-usage.service.ts` | AI usage accounting, summary, and budget checks | Used by AI controller/services and assistant usage UI endpoints | Computes monthly + daily usage limits, reset windows, and deterministic budget block reasons (`AI_DAILY_CAP_EXCEEDED`, etc.) |
| `apps/api/src/imports/imports.service.ts` | Import pipeline orchestration | Uses mapping/migration/provider adapters and shared mobile validation helpers | Batch import processing; commit rejects invalid nonblank mobile instead of silently normalizing loose formats |
| `apps/api/src/intake/intake-booking.service.ts` | Intake booking and OTP flow | Uses Twilio Verify, org billing state, verified-booking credit tables, OTP send audit rows, and shared mobile validation helpers | Public booking journey backend requiring valid Philippine E.164 mobile for OTP-backed holds, safe billing-blocked failures with blocked-send `public_otp_send_events.outcome` audit codes, resend-window reuse, resend cooldown / per-hold send caps, rolling per-mobile/IP caps, per-business daily caps, stable public verify errors (`OTP_INVALID_CODE`, `OTP_MAX_ATTEMPTS`, `OTP_HOLD_EXPIRED`, `OTP_SLOT_CONFLICT`, `OTP_PROVIDER_UNAVAILABLE`), durable provider SID capture, post-send verified-booking credit consumption from the direct current UTC month ledger, and feature-flag aware free-mode fallback when billing is disabled |
| `apps/api/src/help/answer-source.service.ts` | Normalized source-grounded answer envelope assembly | Composes insights, SMS metering, billing, and AI usage services | Read-only assistant prep data responses with deterministic fallbacks, including monthly + daily AI usage canonical fields for assistant/live-usage UI consumers |
| `apps/api/src/help/assistant.service.ts` | OpenAI-native assistant orchestration runtime with staged intent-tool pipeline shared by chat + stream | Composes `AiExecutionService`, `AnswerSourceService`, and `assistant-context` markdown context packs | Deterministic stages (`normalize -> intent -> context -> tools -> openai -> validate -> finalize`), strict JSON-schema response contract + bounded legacy normalization (`action/url -> href`, string confidence mapping), canonical intent-tool registry enforcement, validation diagnostics (`schema/tool/route/confidence`), safe action-chip outputs, and SSE `usage` event emission before `done` for live bar updates |
| `apps/api/src/help/assistant-context.ts` | Layered assistant context-pack builder with query-aware ranking | Used by `assistant.service` and markdown loader | Builds token-budgeted `core/task/data/memory/tools` slices from `docs/assistant-context/*.md`, ranking entries by intent + route/action keyword match before priority fallback |
| `apps/api/src/help/assistant-thread-memory.service.ts` | Persistent thread memory store for assistant conversations | Uses database schema table `assistant_thread_memories` | Loads/saves rolling summary and last N turns by org/user/thread id |
| `apps/api/src/security/pii-crypto.service.ts` | PII encryption/decryption utilities | Used by security/privacy services | Sensitive data protection |
